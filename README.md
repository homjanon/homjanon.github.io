# 个人投资管理系统

纯前端单页应用，管理 **A股 / 港股 / 美股 / 场外基金** 的持仓和盈亏。大部分数据源零配置直连，开箱即用。

## 功能概览

- **四市场覆盖**：A股 / 港股 / 美股 / 场外基金
- **基金双源**：东方财富 pingzhongdata（主，浏览器直连） + 蛋卷 djapi（备用，经通用 CORS 代理，数据质量优于新浪 fu_）
- **市场估值指标**：VIX 恐慌指数 + 纳指100/标普500/沪深300/创业板/红利低波 PE（TTM），基于蛋卷/雪球历史百分位分类
- **智能代码识别**：字母→美股，1-5位→港股，6位自动探测 A股/场内ETF 与场外基金（腾讯财经命中→A股/ETF，东方财富命中→场外基金）
- **多币种换算**：美股 $ / 港股 HK$ / A股基金 ¥，总览统一人民币
- **当日收益**：含时区修正，非交易时段显示休市状态
- **自定义分类**：默认红利/纳指100/标普500，可自行添加
- **饼图**：市场分布 + 品种分布（人民币换算）
- **云端备份**：JSONBin / Gitee 私人仓 / GitHub 私人仓 三种后端任选，一键备份/导入，跨设备同步（上传自动剥离所有 API Key）
- **自动同步**（可选）：持仓变更自动上传、打开时确认拉取云端更新，打通「电脑算、手机看」
- **数据导出/导入**：JSON 文件备份恢复
- **基金补仓**：按加仓金额与加仓当日单位净值加权计算新增份额与成本价，默认同步扣减对应币种现金余额；当天净值由东方财富自动获取（可修改），历史日期可手动输入净值
- **PWA**：可添加到主屏幕，离线缓存
- **响应式**：桌面 / 平板 / 手机自适应

| 线路 | 勾选 | 股票 | 基金（主源→备用，自动切换） |
|------|------|------|------|

| **三** | 都不勾 | Finnhub(美股) + 必盈(A股) + Yahoo(港股) | 东方财富 pingzhongdata → 蛋卷 djapi（需代理） |

> 基金数据：主源东方财富 `pingzhongdata`（浏览器直连、免代理免鉴权）；备用蛋卷 `djapi/fund/{code}`（免登录/免 Referer、UTF-8 干净 JSON，但响应无 CORS 头，须经「通用 CORS 代理」转发，详见下方）。天天基金接口已于2026年全面失效(返回404)，已从代码中移除；新浪 `fu_` 因覆盖不全（部分基金返回空）且需 GB18030 解码，已弃用并替换为蛋卷。
> 线路一/二免 API Key 开箱即用（股票均走腾讯，基金源一致）。线路三需自行申请 Finnhub 和必盈 Key。

### 场外基金备用源：蛋卷 djapi（需自建代理）

蛋卷 `https://danjuanfunds.com/djapi/fund/{代码}` 免登录、免 Referer，返回干净的 UTF-8 JSON（含名称/单位净值/日期/日涨幅），覆盖全（含东方财富/新浪查不到的基金）。但服务端**不返回 CORS 头**，浏览器直连与公共 CORS 代理（codetabs/allorigins）均被跨域拦截。

**启用方法**：部署一个 Cloudflare Worker（约 15 行）作为通用 CORS 代理，把其地址填到设置页的「CORS 代理 URL」即可。Worker 示例：

```js
// Cloudflare Worker：通用 CORS 代理（蛋卷等无 CORS 头资源经此转发）
export default {
  async fetch(request) {
    const url = new URL(request.url);
    const target = url.searchParams.get('url');
    if (!target) return new Response('missing url', { status: 400 });
    const upstream = await fetch(target, { headers: { 'User-Agent': 'Mozilla/5.0' } });
    const resp = new Response(upstream.body, upstream);
    resp.headers.set('Access-Control-Allow-Origin', '*');
    return resp;
  }
};
```

> 若不部署该代理，蛋卷备用会静默失败，基金仍由东方财富主源提供（无副作用）。该 Worker 同时可作为通用 CORS 代理提升整体可靠性。

### 云端备份（三种存储后端，设置页「同步方式」切换）

设置页顶部新增「同步方式」下拉，支持三种后端，任选其一，其余字段按所选方式显隐：

| 同步方式 | 后端 | 需填字段 | 适合场景 |
|---|---|---|---|
| **JSONBin**（默认，原有） | jsonbin.io 云端 | API Key + Bin ID | 海外；老用户平滑兼容 |
| **Gitee 私人仓** | 你自己的 Gitee 私人仓库 `data/user-data.json` | 私人令牌 + 仓库(owner/repo) | 国内访问最顺，纯前端直连 |
| **GitHub 私人仓** | 你自己的 GitHub 私人仓库 `data/user-data.json` | 细粒度 PAT + 仓库(owner/repo) | 最小权限（PAT 可限定单仓），CORS 稳 |

- **Gitee / GitHub 原理**：纯浏览器直连对应平台的 Contents API（`GET` 拿 `sha` → 有则 `PUT` 更新、无则 `POST` 创建），把 `user-data.json` 写进你指定的私人仓库，**无需任何服务器/代理**。
  - Gitee 私人令牌：https://gitee.com/profile/personal_access_tokens → 勾 `projects`（项目读写）权限即可；Gitee 令牌为**账号级**（非单仓），建议短有效期或专用小号。
  - GitHub 私人令牌：用**细粒度 PAT**，仅授权那一个私人仓库的 `Contents` 读写，安全性最佳。
  - 中文 UTF-8 已处理（`btoa(unescape(encodeURIComponent(...)))`），持仓中文名不会乱码。
- **首次使用**：选好方式 → 填令牌/仓库/路径 → 点「☁️ 备份到云端」（路径默认 `data/user-data.json`，父目录会自动创建）→ 之后「📥 从云端导入」即可跨设备恢复。

> 🔒 **安全**：上传云端前会自动**剥离所有 API Key**（Finnhub / 必盈 / JSONBin / 云同步令牌 `cloudToken`），本地保留正常使用，密钥不会驻留云端。云同步令牌仅存于你浏览器 localStorage，不上传。

### 自动同步（可选，默认关闭）

打通「电脑算、手机看」：电脑上改动持仓后自动上传云端，手机打开页面时提示拉取最新数据。

- **开启方式**：设置页勾选「☁️ 自动同步」，前提是已选好同步方式、填妥对应凭据（JSONBin 的 Key、或 Gitee/GitHub 的令牌+仓库）并手动备份过一次
- **上传**：持仓 / 现金 / 分红任一改动后，**3 秒**合并自动上传一次（已剥离所有 Key），避免连续操作刷爆请求
- **下载**：每次打开页面检查云端 `syncTime`，**比本地新才询问**是否拉取——**需你确认，绝不静默覆盖**；拉取会保留本地已填的 Key
- **仅同步持仓数据**（assets / cash / dividends），配置不自动上传（更安全）
- **额度**：日均约 20 次，JSONBin 免费额度 1 万次/月、GitHub/Gitee 个人仓库写入远低于其 API 限额，均安全
- 关闭自动同步后，仍可用手动「备份到云端 / 从云端导入」按钮

### 清除数据

设置页底部的「🗑️ 清除所有数据」会清除全部资产、配置和指标缓存。

1. 点击「添加资产」，输入代码自动识别市场

## 分红提示与自动复投

打开页面时会自动检测持仓中**已实施分配、且除权日 ≤ 今日、尚未记录**的分红（A股走东方财富 `RPT_SHAREBONUS_DET`；基金走东方财富 `pingzhongdata` 的每份派现 + 除权后净值）。

- **逐资产横幅**：检测到的分红以「每条一项」列表展示，可逐个**「记录」**（打开分红模态框，自动带入每股/每份分红、除权日、报告期，均可在录入时修改）或**「稍后提醒」**（暂存该笔，本次会话不再弹出；下次打开仍会检测，但已记录的不会再弹）。
- **去重修复**：分红记录现完整保存「除权日 + 报告期」，并以 `资产代码 + 除权日` 做去重——**解决了此前每次打开都重复弹分红的问题**。
- **股票类**：手动填写每股分红即可，分红作为现金到账。
- **基金自动复投（红利低波等）**：在资产编辑/新增时，若类型为「基金」，会出现「分红自动复投」勾选框；**品种含「红利低波」或代码为 `020602` 时默认勾选**，其余基金默认不勾。开启后，该基金分红到账时**自动按除权后净值折算份额、直接增加持仓（加权平均成本价），不进现金**，并留下一条 `status: reinvested` 的分红记录 + Toast 提示；若检测源未返回复投价，则退化为现金到账（同普通分红）。手动复投入口（分红记录卡片上的「复投」按钮）仍保留，用于把已到账现金再投回持仓。

> 自动复投为静默执行（无确认弹窗），便于「电脑算、手机看」场景下无人值守完成。如需关闭，取消对应资产的「分红自动复投」勾选即可。

## 市场估值指标卡8 / 卡9 显示优化

秋哥操作（卡8）与一句话总结（卡9）同源 `xiaoxu-fear` 的 `qiuge_report.json`，二者在同一 3 列网格中保持与其他 7 张卡**完全相同的尺寸**。

- **卡8 秋哥操作 — 主打「动作」**：把仓位信号升级为彩色徽章主视觉（🟢 加至7成 / 🟡 仓位≤X成 / 🔴 全面降仓），下方依次显示指数点位（带涨跌，涨红跌绿）与生命线/压力位；卡片底部嵌入**紧凑版「关注(watch)」小蓝条块**（`qiuge-watch-sm`，10px 字号、用「 · 」连成一段、不截断、紧凑 padding）。`watch` 取自 `qiuge_report.json` 的 `watch` 数组（如 中国石油/水晶光电/科创50ETF/半导体轮动 等带价位提示的盯盘标的）。`outlook`（展望）已从界面完全移除。
- **卡9 秋哥精选标的 — 只展示 `picks_detail` 标的明细**：整卡用于呈现秋哥精选标的清单，每个标的双行紧凑展示——首行 `名称 + 代码 + 现价`（现价右对齐蓝色），次行 `操作建议 + 仓位徽章`（仓位以琥珀色小徽章呈现）；卡片底部保留一行 tiny 数据日期。字号 11–13px，信息密度高、竖排 5 个仍可撑满整卡。标题由"一句话总结"改为"秋哥精选标的"。
- **去重/显示修复**：卡8 信号原 `positionMax*100` 会把 0.6 误显为「60成」，已改为 `Math.round(positionMax*10)`（正确显示「6成」）。
- 全部改动**只改填充内容、不增删 DOM 节点、不动网格与卡片尺寸**；长文均用 `-webkit-line-clamp` 锁行数防溢出。

## 刷新与分红提醒优化

- **单资产刷新同步净值日期**：基金卡片上的「刷新」按钮此前只更新「当前价（最新净值）」，但价格旁边的**净值日期（`navDate`）不会跟着刷新**，只有右上角「刷新数据（全部）」才会同步。现已在 `refreshAsset()` 回写 `navDate`，单卡刷新与全部刷新行为一致。
- **分红提醒改为「除权日 ±3 天」窗口**：此前检测只过滤「`exDate ≤ 今天」、没有时间下限，导致持仓里历年分红（如招行 2012/2014/2015…）只要未记录就每次打开都弹。现新增 `REMIND_WINDOW_DAYS = 3` 常量与 `withinRemindWindow(exDate)` 判断，仅当 `|今天 − 除权日| ≤ 3 天` 才纳入提醒——历史分红自然被排除，仅在实际除权日前后的 3 天窗口内提醒一次（记录或「稍后提醒」后即停）。红利低波(020602) 因自动复投当天即记录，本身不会弹。窗口天数改一个常量即可放宽/收紧。

## 场内 ETF / LOF 并入「股票」

- **问题**：`563300`（华泰柏瑞中证2000ETF）等场内 ETF/LOF 既不是普通 A股 股票、也不是场外基金。旧逻辑只做「A股 vs 场外基金」二选一：腾讯财经能返回就判 `a-stock`、否则用东方财富净值探测判 `fund`。当腾讯偶发失败时，场内 ETF 会被误判为**场外基金**——导致取价变成滞后的「单位净值」而非实时成交价，且冒出「分红自动复投」勾选框（那是给场外基金用的）。
- **修复**：`identifyAssetType()` 现以**腾讯财经返回的「证券类型」字段**（索引 61：`GP-A`=股票 / `ETF` / `LOF`）为识别依据。场内 ETF/LOF 与普通 A股 均**并入 `a-stock`（股票）**——名称与实时价都取自腾讯财经（实测 `sh563300` → 「中证2000ETF华泰柏瑞」+ 实时价 1.299，两者均正确）。另加一道**代码前缀兜底**（`5x`/`15`/`16` 开头）防止腾讯无返回时仍误判为场外基金。场外基金（如 `020602` 红利低波）因不在腾讯上市，自然走东方财富净值探测 → `fund`，自动复投逻辑不受影响。

### 上交所代码前缀映射修正（5 开头 ETF 乱名修复）

- **问题**：取价/取名时 `getTencentCode()` 对 `a-stock` 仅把 `6` 开头映射到 `sh`（上交所）、其余一概 `sz`（深交所）。但 `5xxxxx`（如 `563300`、`510300`、`588000` 等沪市 ETF/指数/债券）同属**上交所**，被误拼成 `sz563300` → 返回无关品种乱名「上海2419」+ 错价（如 100.00）；而 `1xxxxx`（如 `159915` 创业板ETF）属深交所、`sz` 正确，故不受影响。该 bug 同时污染名称与实时价。
- **修复**：`getTencentCode()` 改用 `/^[569]/.test(code)` 判断——`5`/`6`/`9` 开头 → `sh`（上交所），其余 → `sz`（深交所）。单行改动同时修好名称与实时价，`563300` 现正确显示「中证2000ETF华泰柏瑞」+ 实时价，`159xxx` 行为不变。
